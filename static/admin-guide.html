ADMINISTRATOR REFERENCE | VERSION 1.0.41

Admin and Update Guide

Administration, REDCap-primary data handling, local AI, backup, deployment, and rollback checks.

Return to application

Roles and accounts

  • Administrators manage application users and have all coordinator permissions.
  • Coordinators can create/load assessments, manage groups and assignments, reset group passwords, load REDCap data, and view all reports.
  • Group accounts are phase-specific and see only assigned work.
  • Coordinator passwords remain valid until an administrator resets them.
  • Verify role restrictions after every authentication or navigation update.

Assessment administration

  1. Select country and month/year in the Inventory Assessment data panel.
  2. Use Load REDCap data only for an existing assessment and Add new data for a blank one.
  3. Assign Inventory tools, Profiling systems, and Gap Analysis domains separately.
  4. Confirm Member State saves reach the intended REDCap country-period record.
  5. Confirm Test Country remains temporary, displays the temporary-only status, and creates no REDCap record.
  6. Confirm loading, reporting, and logout do not duplicate a record.
  7. Verify Analysis defaults to the active assessment while remaining editable.

Protected files and data

  • REDCap is the primary assessment database for Member State data.
  • africa_cdc_web.db contains accounts, sessions, permissions, groups, assignments, settings, and temporary workspace state.
  • .env contains protected REDCap, password-security, and optional AI settings.
  • The adjacent .env is authoritative for desktop, source, and packaged launches. Preserve it during updates to keep passwords valid.
  • Never disclose the REDCap token or password pepper.
  • Stop the executable before copying or replacing its database or executable.

Local report assistant

  • Default provider: Ollama at http://127.0.0.1:11434.
  • Default model: qwen3:4b-instruct.
  • The app automatically attempts to start the local Ollama service.
  • Simple and complex requests have different evidence and output limits to control memory.
  • Responses stream into the chat. Complex analysis remains slower on CPU-only computers.
  • Only selected report evidence is sent locally; credentials and unrelated assessments are excluded.
  • Standard Unified DHIS2 toolkit output must omit the separate Validation gates and indicators section and the automated Evidence check warning that lists unsupported numerical expressions.
  • Assistant responses can be exported through Download latest response in Word.
  • Chart prompts use deterministic browser calculations and can export a combined PNG; Ollama does not calculate chart values.
  • Local analysis and exports work offline after report data is loaded, but REDCap retrieval and saving still require connectivity.

Useful checks: ollama list, ollama ps, and Invoke-RestMethod http://127.0.0.1:11434/api/tags.

Portable deployment: local AI prerequisite

The portable assessment executable does not contain Ollama or the AI model. On every new computer where the report assistant is required:

  1. Install Ollama for Windows using the organisation's approved software-deployment process.
  2. While internet access is available, run ollama pull qwen3:4b-instruct.
  3. Run ollama list and confirm qwen3:4b-instruct is present.
  4. Start the assessment app and confirm its assistant header shows Local AI - qwen3:4b-instruct.
  5. Test one simple question and one complex analysis before handing the computer to users.

After installation and model download, local AI can operate without internet when report data is already loaded. Without Ollama, the assessment forms, standard reports, charts, PNG downloads, and Word exports remain available, but full local-AI analysis is unavailable. REDCap loading and saving continue to require network access.

Optional online AI provider

  1. Obtain organisational approval for external processing and the provider's retention terms.
  2. Add AFRICA_CDC_OPENAI_API_KEY and, optionally, AFRICA_CDC_OPENAI_MODEL to the private .env file, then restart the app.
  3. Open User Management as an administrator.
  4. Under Report assistant provider, select OpenAI API, confirm authorisation, save, and test the provider.
  5. Confirm the assistant header says Online AI before use. Return the selector to Local Ollama to disable online processing.

Local Ollama remains the default. Online requests send only the generated report and current question, use store: false, and do not include REDCap records, the supporting-evidence JSON, credentials, or chat history. The app does not persist report or response content in SQLite. Provider-side retention remains governed by the approved provider account and contract. Never enter an API key into the browser interface or database.

Before an update

  1. Ask users to save and log out.
  2. Verify required new data in REDCap.
  3. Stop the application.
  4. Back up africa_cdc_web.db, .env, and the current executable.
  5. Test medium- or high-risk changes with copied data and a controlled REDCap record.
  6. Record files changed and whether database, REDCap, or AI configuration changes are involved.

Required post-update checks

  1. Administrator, coordinator, and group logins work before and after restart with the preserved .env.
  2. The main forms open blank until an assessment is created or loaded.
  3. REDCap load and Member State save use the correct country/month record without duplicates.
  4. Test Country remains temporary and REDCap contains zero Test Country records.
  5. Standard Excel import displays immediately and maps every Profiling response/comment, including Opportunities & Challenges.
  6. Blank dropdowns remain No response and national totals exclude blank and subnational values.
  7. The five-part Profiling summary and evidence-linked consolidated recommendations are complete and accurate.
  8. Inventory, Profiling, Gap Analysis, assignments, and password reset work.
  9. Analysis defaults, three report types, Word, PDF/print, dashboards, and Excel exports work.
  10. A Unified DHIS2 toolkit response and its Word export omit Validation gates and indicators and the unsupported-numerical-expression Evidence check warning.
  11. Assistant Word export opens successfully and chart prompts display charts and download a valid PNG.
  12. Ollama auto-start, status, streaming, a simple question, and a compact evidence-linked recommendation request work.
  13. Only one application instance is listening on the configured port.

Rollback

  1. Stop the failed update and preserve its error information.
  2. Restore the previous executable.
  3. Restore the database only if it was changed or damaged.
  4. Preserve `.env` unless configuration rollback is explicitly required.
  5. Recheck health, login, roles, REDCap load/save, duplicate prevention, reports, and Ollama.
  6. Document the failure and corrective action.

Detailed build commands, test requirements, and change-record template are maintained in APPLICATION_UPDATE_GUIDE.md in the source folder.
